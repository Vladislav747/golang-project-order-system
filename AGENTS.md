# AGENTS.md

Инструкции для AI-агентов в этом репозитории.

**Единый источник правил.** Codex и Cursor читают этот файл. Claude Code — через [`CLAUDE.md`](./CLAUDE.md) (`@AGENTS.md`); отдельный `CODEX.md` не нужен.

## Язык и стиль

- Отвечай пользователю **на русском**.
- Пиши коротко и по делу. Не пересказывай задачу и не раздувай ответ.
- Не коммить и не пушь, пока пользователь явно не попросил.

## База знаний

Перед работой по фиче/багу:

1. Загляни в [`knowledge-base/`](./knowledge-base/) — индекс в `README.md`.
2. При необходимости уточни дизайн в [`PLAN.md`](./PLAN.md) и код.
3. После существенного прогресса **обнови** релевантную заметку в `knowledge-base/` (статус, дыры, пути к файлам). Не дублируй весь план.

Не клади в knowledge-base секреты (`.env`, ключи, токены).

## Как мы работаем над кодом

- Пользователь часто пишет код сам; агент направляет шагами, ревьюит, правит точечно по просьбе.
- Не переписывай большие куски «за компанию» — только то, о чём попросили.
- Сохраняй существующий стиль пакета (интерфейсы у потребителя, zap, pgx, слои из README).

## Стек и процессы

- Go-сервис заказов: HTTP/gRPC + Kafka consumer (`cmd/order-service`), outbox relay/cleaner (`cmd/outbox-worker`).
- Слои: model → repository → service → transport/handler. Транзакции открывает service/worker, не repository.
- **Не** запускать relay одновременно в обоих бинарниках.

## Конвенции

- Импорты: **gci** — stdlib → third-party → `github.com/Vladislav747/golang-project-order-system/...` (см. `.golangci.yml`).
- Тесты: unit рядом с пакетом; integration/e2e под `tests/` с build tags.
- Сообщения коммитов — коротко, в стиле истории (`git log`), фокус на зачем.

## Чего не делать

- Не выдумывать API мимо `PLAN.md` / существующих хендлеров без согласования.
- Не коммитить `.env`, бинарники, мусор IDE.
- Не ослаблять DLQ-инварианты: consumer Mark только после успеха или успешного DLQ; sink — Kafka, потом DB.
